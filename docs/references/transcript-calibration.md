# 长篇课程录音：转写与校订方法论

> 来源：一次 29 讲、约 50 小时的哲学史课程录音（先刚《西方哲学史》上 15 讲 + 下 14 讲）。
> 上半部有现成但未经校订的转写稿，下半部从零转录。全稿 68.9 万汉字，改动 1,835 处。
>
> 这份文档只写**能复用的判断**。事故过程留在正文里，因为"为什么会错"决定了
> "下次怎么早发现"。

---

## 零、一句话的总纲

**转写稿的错误分布不是随机的，它由三层决定：录音响度、分块长度、模型词表。**
按这三层从上往下排查，比逐句听改快一个数量级。反过来，一上手就逐句校对，
你会在第 3 讲放弃。

---

## 一、先看病征，别先怀疑模型

拿到一份转写稿，别急着读。先量四个数：

| 指标 | 怎么算 | 健康值 | 说明 |
| --- | --- | --- | --- |
| **段/分钟** | VAD 切出的语音段 ÷ 音频分钟数 | **8–20** | 掉得最早，识别前就能看出来 |
| **字/分** | 正文汉字数 ÷ 音频分钟数 | 中文讲课 **190–260** | 最灵敏的单一指标 |
| **空段率** | 识别为空的块 ÷ 总块数 | **< 2%** | 超过 15% 必定有问题 |
| **时长核对** | 最后的结束时间 vs 视频时长 | 差 < 1% | 差太多说明尾部被截 |

「段/分钟」是**这一轮补上的**，也是我现在最先看的一个：它和识别质量无关，
纯粹反映"切分有没有把语音找全"。20 分钟只切出 36 段（1.8 段/分钟）时，
字/分必然是 31 —— 这时候该动的是切分，不是模型，也不是增益（见第二节）。

### 实测对照（同一门课，同一模型）

| 讲次 | 音频电平 | 空段 | 字/分 | 结论 |
| --- | --- | --- | --- | --- |
| 下·第1讲（原样） | −27.8 dBFS | 78 / 397 | **90** | 病态 |
| 下·第1讲（归一后） | −18 dBFS | 1 / 397 | **191** | 正常 |
| 下·第2讲 | −26.8 dBFS | 0 | 236 | 正常 |
| 上·各讲（120s 分块） | 健康 | 0–1 | 212–253 | 正常 |

同一段 20 分钟素材的对照更刺眼：

```
原样       80 段  63 非空  17 空  1626 字   81 字/分
归一化后   80 段  80 非空   0 空  4159 字  208 字/分   ← 2.6 倍
```

**这就是最容易踩的坑**：模型不报错、不警告、退出码 0，只是安静地少给你一半内容。
如果你不量字/分，就会拿到一份"读起来通顺、但少了整整一半"的稿子。

⚠️ 但上面这段是**固定分块、无 VAD** 的管线。同一批音频换成 VAD 切分后，
"归一是解药"这个结论**不成立**——真正的主因是 VAD 在低电平上漏检。
完整的复现与纠正过程见第二节，**那一节比这段更值得读**。

### 病征 → 处方

| 病征 | 先查这个 | 处方 |
| --- | --- | --- |
| **段/分钟 < 5** | VAD 是否漏检 | **改能量切分重跑**（见第二节；本 CLI 已自动） |
| 字/分 < 120 且段/分钟正常 | 音频 RMS 电平 | 增益归一化到 −18 dBFS 重跑 |
| 空段率高但字/分正常 | 是否含大段音乐/静场 | 正常，忽略 |
| 字/分正常但句子破碎 | 分块长度 | 加长分块（见第三节） |
| 结尾突然中断 | 时长核对 | 下载不完整，重下 |
| 专名大面积错但通顺 | 词表 | 校订阶段处理（见第五、六节） |

## 二、音量与切分：先查切分，再查增益

这一节是**被实测纠正过**的。我最初的结论是"录音偏轻 → 模型整句丢弃 → 归一化是解药"，
写进文档后做端到端复现，才发现**因果搞错了**。留在这里的过程比结论更有用。

### 2.1 最初的测量（固定分块、无 VAD）

同一段 20 分钟素材，按固定 15 s 切块喂给模型：

```
原样       80 块  63 非空  17 空  1626 字   81 字/分
归一化后   80 块  80 非空   0 空  4159 字  208 字/分
```

整讲（99 分钟）归一化后空块从 78 降到 1，正文从 8,925 字涨到 18,933 字。
于是我写下"归一是主因"，并把它设成默认开启。

### 2.2 端到端复现（VAD 切分）

在技能的 VAD 管线上重做同一件事，**结果完全不同**：

| 条件（同一段 20 分钟、−27.7 dBFS 讲座） | 段数 | 正文 | 字/分 |
|---|---|---|---|
| VAD 切分 + 不归一 | 36 | 626 | **31** |
| VAD 切分 + 归一 | 94 | 1,513 | **76** |
| 能量切分 + 不归一 | 67 | 4,366 | **218** |
| 能量切分 + 归一 | 74 | 4,337 | **217** |

读法：

1. **主要瓶颈是 silero VAD 的门限，不是识别模型。** 低电平时 VAD 把大部分语音
   判成静音（20 分钟只切出 36 段 = 1.8 段/分钟），喂给模型的东西本来就不够。
2. 归一化对 VAD 路径有效（31 → 76），但只是把"几乎全聋"抬到"半聋"。
3. **换切分方式一步到位**（76 → 218），而且不需要归一也很正常。

### 2.3 正确的做法

```
低电平音频
   ├─ 第一步：增益归一（便宜、几乎无害，默认开）
   └─ 第二步：检查"段/分钟"。VAD 切分低于 5 段/分钟 → 改能量切分重跑，取字多者
```

判据要用**段/分钟**，不要只用字/分：段数掉得**更早**，而且它在识别之前就暴露问题
（字/分要等识别完才知道）。

### 2.4 两个实现细节

- **限幅优先于达标。** 削波会制造新的识别错误，比声音小更糟。录得特别轻的文件
  提不满 −18 dBFS 是正常的，记下 `clipped=True` 即可。
- **全零/静音输入要短路。** `log10(0)` 是 `-inf`，写进 JSON 会变成 `NaN` 或抛异常。

### 2.5 这条给所有人的教训

> **"改了 A 之后指标变好"不等于"A 是原因"。**

我改变量时换了两样东西（加了归一化，同时也换了音频切片），就敢断言因果。
真正的原因是切分方式——它恰好和归一化一起被换了。控制变量这件事，
在"指标明显变好"的时候最容易被跳过，因为好消息让人不想再查。

## 三、分块长度：时间码粒度 vs 句子完整度

| 分块 | 时间码粒度 | 句子被切断的概率 | 适合 |
| --- | --- | --- | --- |
| 15 s | 细 | 高 | 需要精确定位 |
| 60 s | 中 | 中 | 折中 |
| 120 s | 粗 | 低 | 只要通读 |

实测 120 s 分块的下上半部达到 212–253 字/分、空段 0–1，质量并不比 15 s 差。

**没有免费的午餐**：短块给的时间码准，但句子容易在块边界被切成两半
（表现为相邻两条各带半句）。如果你不打算合并句子（通常不该合并，见第八节），
就选长一点的块。

**但"分块长度"是次要问题，"用什么决定切点"才是主要问题。** 固定时长切块
（不看内容）和 VAD/能量切分（跟着语音走）是两种东西，第二节那张表说明：
低电平音频上两者能差 7 倍（31 vs 218 字/分）。固定切块的唯一优势是时间码好算，
代价是会把静音和语音混在同一块里——这正是低电平时整块被判空的原因。

## 三·五、多分 P 的视频（讲座/课程）有一个专门的坑

课程类视频几乎都是"一个 BV 号挂十几二十个分 P"。B 站 `view` 接口的语义是：

- 顶层 `duration` = **所有分 P 之和**（14 讲 → 23.7 小时）
- 顶层 `cid` = **只是第 1 个分 P**

拿这两个字段配着用，就会得到"API 说 23.7 小时、我只下到 1.6 小时"的假象。
用"下载时长 < API 时长 × 0.2"去判"充电专属预览"时，一个**完全正常的公开课程
会被判成充电专属**，直接抛异常，一个分 P 都转不出来。这一次实测就是这样撞上的。

正确做法：

1. 分 P 的 `cid` / `duration` / `part` 一律从 `pages[p-1]` 取；
2. 完整性校验只和**本分 P 的时长**比；
3. **文件名必须带页码**（`BVxxx-p02.md`），否则十几讲互相覆盖——
   这个错误很隐蔽：每次都"成功"，只是最后只剩一讲；
4. 临时音频也要带页码，否则第二讲会覆盖第一讲、再被当成第一讲识别。

顺带一个与校订相关的观察：分 P 标题往往就是"1、2、3"这种，从中**看不出上课日期**。
`pubdate` 是上传日，`view_points` 是空的（见 SKILL.md 里同一结论），
所以"这一讲是哪天讲的"通常**取不到**，不要猜、不要填运行日。

## 四、分轨（说话人）基本上不可用

某平台给出的说话人编号长这样：

```
[说话人1] 那个亚里士多德…
[说话人2] 出生。
[说话人1] 他工作，他死了。
```

同一个人的一句话被切成三个"说话人"，切换点在一句话中间。
一节课里 `说话人 1/2/3` 各出现 3649/3069/208 次——但这是**单人讲授**。

**处置**：当作只有一个说话人，把标签统一成 `说话人 1`，
**逐条保留时间码、不合并句子**。这样既纠正了错误，又没破坏可定位性。

不要试图"修正"分轨，也不要按分轨做内容切分。它的错误率高于它能提供的价值。

## 五、校订：三层，顺序不能乱

### 5.1 三层各管什么

| 层 | 管什么 | 例 | 规则表里怎么写 |
| --- | --- | --- | --- |
| **词典层** | 同一走音的多种写法 | `斯明诺纳/斯频诺上/斯宾诺少 → 斯宾诺莎` | 短键，一音多条 |
| **定点层** | 需要上下文才敢定的 | `他落网历史还是在德国梦态里面 → 诺瓦利斯还是在德国浪漫派里面` | 长键，把上下文一起圈进来 |
| **机械层** | 叠字、全角标点、多余空格 | `比较比较 → 比较`；`， → ,` | 前两项由工具做，叠字建议写成显式规则 |

**顺序不用你想**。历史做法是"定点层先跑、再跑一遍词典层"（`apply → dictionary → apply again`），
因为定点替换产生的新文本里可能还有走音。现在 `scripts/calibrate.py` 把所有规则编成一条
正则、长键优先、跑到不动点，这两点自动成立；你只需要决定**每条键圈多大上下文**。

### 5.2 三个会让替换自我破坏的陷阱

**① 短键污染已经改好的文本**

```
键 `女性批判 → 理性批判`，但正文里已经有正确的 `纯粹理性批判`
→ 命中 "理性批判" 里的 "性批判"？不，是命中已改好的 "纯粹理性批判" 的尾部
→ 结果：纯粹理性批判 → 纯粹女性批判   （方向反了）
```

修法：加一条**空转守卫** `"理性批判": "理性批判"`。听上去荒唐，
但它就是最省事的"保护已正确形态"手段。

**② 最长优先的 tie-break**

词典按长度降序匹配，但**等长时按原顺序**。曾出现
`莱布尼茨斯` 和 `斯林诺莎` 都是 4 字，前者先命中，把原句里的
"莱布尼茨、斯宾诺莎" 吃成了 "莱布尼茨斯…"（11 处）。

修法：把**组合形态**也收进词典（`莱布尼茨斯林诺莎 → 莱布尼茨、斯宾诺莎`），
让最长的那个赢。

**③ 键是正确词的子串**

`拉克利特 → 赫拉克利特` 这个键，在正文 `赫拉克利特` 里也出现。
单遍交替下它会在**已经正确**的词里再命中一次，变成 `赫赫拉克利特`，
而且每跑一遍多一个字。

修法：加**空转守卫** `赫拉克利特<TAB>赫拉克利特`（改后=原）。长键先赢，
该位置先命中守卫，正确形态原样放过。`scripts/calibrate.py` 不收敛时会直接点出键名。

**④ 键里含着另一条规则的产出（线序依赖）**

`曾森 → 曾参` 与 `曾参和有弱 → 曾参和有若` 同时在场，而正文写的是"曾森和有弱"。
第一遍只能改前半——"曾参和有弱"这个键当时还不存在；第二遍才命中。

这是单遍交替**挡不住**的一类，也是它唯一的真实短板。修法：工具自动跑到不动点
（上限 8 遍），把 `passes > 1` 报出来；更好的修法是把键写成不依赖上游结果的形式
（`和有弱 → 和有若`）。

## 六、怎么高效发现专名走音

逐句读 30 万字是不现实的。用这四个办法代替：

### ① 全文枚举变体

对每个已知人名，用它的**后两字**去全文扫，把所有前后片段列出来，
按频次排序。一个讲座里同一个名字常有 5–6 种写法，它们会**成簇**出现。
这一招把"找错字"变成"看频次表"。

### ② 上下文锚点

专名附近常有自带校正信息的内容：

- 「卢瓦利斯…他的女朋友就叫索菲亚」→ 诺瓦利斯（Novalis 的未婚妻 Sophie）
- 「维拉莫维斯写文章攻击他」→ 维拉莫维茨（Wilamowitz 攻击尼采《悲剧的诞生》）
- 「他说自己早在赫拉克利特那里就有了」→ 尼采

**一旦找到一个锚点，就能反推整段**。这比听 20 遍音频有效。

### ③ 字母串 → 德语／希腊语

这次最反直觉的一类：识别结果里出现 `JS`、`bug`、`block`、`boss`、`ST`、`DMO`。
它们是模型把**德语词/希腊词**听成了英文单词：

| 识别成 | 实际 | 判断依据 |
| --- | --- | --- |
| `JS` (15 次) | *Wissenschaft* | 「JS 这门学科由谢林和黑格尔共同奠定」 |
| `bug` (104 次) | *Begriff* | 黑格尔语境 |
| `block` | *Platon* | |
| `boss` | *Sokrates* | |
| `ST` | *Sein* | 巴门尼德 τὸ εἶναι |
| `Badcase` | *Parmenides* | |
| `DMO` | *Timaios* | 《蒂迈欧篇》 |
| `Phoenix` / `φύσις` | φύσις | 「Phoenix 和 nomos 的对立」 |
| `Phoenix` / `σχῆμα` | σχῆμα | 装饰语境（同一词形，两个意思） |

**注意最后一条**：同一个英文字符串在不同上下文里对应不同的词。
所以字母串的还原**必须带上下文**，不能做成全局词典。

### ④ 中文同音词的成系统错误

这次挖到两处最值钱的：

- **`理财` = 尼采**，64 处，横跨 9 讲。原稿里"尼采"一次都没出现。
  语料证据：`理财` 出现在"叔本华的学生""攻击苏格拉底""自认为赫拉克利特的先行者"
  等上下文里，而这些全是尼采。
- **`职业` = 哲学**：`职业史` = 哲学史，`职业家` = 哲学家。

**教训**：一个 3–5 字的高频怪词，如果语法位置永远像个专名，去查它。

## 七、校验必须独立于修复

校订脚本和校验脚本不能共享同一套假设，否则一起错。

### 7.1 老办法：按行判"残留"（现在基本用不上了，但要明白为什么）

历史上的校订是"一条条规则顺序替换"，改完得回头问一句：有没有哪一行还留着错的？
按子串判会误报（短键落在正确词内部），所以改成按行判：

```python
# 错：短键落在正确词内部就误报
if key in text and value not in text: ...

# 对：问的是"有没有一行上，错的在、对的不在"
for line in text.split("\n"):
    if key in line and value not in line: ...
```

这一改，假警报从 36 条降到 0。

**但换成"单遍交替 + 不动点"之后，这个检查永远不会响了**：正文里每个键都必然
已经被换掉，剩下的"残留"只可能是规则没列出的**第三种写法**，而那种写法按行判也看不见。
2026-10 写 `scripts/calibrate.py` 时照抄了这段，自测发现一次都不触发，于是删掉，
换成两个真会响的：

| 检查 | 抓什么 | 抓到时的意思 |
| --- | --- | --- |
| **零命中规则** | 规则写了却没生效 | 键打错 / 这份稿里本来没有 / 被更长的规则遮蔽 |
| **不收敛** | 规则自己喂自己，每遍多一个字 | 缺空转守卫 |

教训不是"按行判错了"，而是**检查写了就要测它会不会响**。一个永远不会触发的校验，
比没有校验更糟——它让人以为查过了。

### 7.2 断言每条规则都真的落地了

```python
for page, key, value in TARGETED:
    assert key in src,          "这条规则根本没命中"
    assert value in dst,        "改了但没进去"
```

不写这三行，你会有一堆"写了但没生效"的规则，而且永远不知道。

### 7.3 跑到不动点，而不是"跑一遍就完"

**连跑两遍，第二遍的改动数必须是 0。** 不是 0 只有两种可能：

- **规则在吃自己产生的文本**（第五节②）——这是 bug，每遍多一个字，永不收敛；
- **键里含着另一条规则的产出**（第五节④）——这是正常的，再跑一遍就对了。

`scripts/calibrate.py` 两种都兜住：循环到不动点、上限 8 遍；`passes > 1` 打印出来，
不收敛直接报错并点出键名。所以你要看的不是"是不是一遍"，而是**收敛用了多久、
第 2 遍改的是哪条键**。

### 7.4 别用同一个模型做"交叉印证"

我试过：拿机器 ASR 的结果去校核已有的转写稿，用时钟对齐后逐条比对。
**结果：0 条可用建议。** 因为两次都是同一个模型，错的地方一样错、
对的地方一样对——噪音被当成了信号。

真正的独立证据只有三种：**音频本身、上下文语义、外部资料**（人名生卒、书名、
他人引述）。同模型第二次运行不在此列。

## 八、不要做的事

| 别做 | 为什么 |
| --- | --- |
| 合并相邻短句 | 破坏了时间码定位，而且你并不知道说话人是不是真的停顿了 |
| 改写句子／删从句／补内容 | 这是转写稿，不是编辑稿。读者要的是"他到底说了什么" |
| 补一个"听起来对"的人名 | 猜错比留着错更糟：留着错，读者知道这里有问题；猜错，读者以为是对的 |
| 相信文件头的时间戳 | 论文这次：同一批文件头写着 9:54 / 10:18 / 10:19 / 10:23 / 10:24，是录音软件的**排课时刻**，不是内容时间。视频也拿不到真实日期（B站 `view_points` 为空，`pubdate` 是上传日） |
| 为整齐统一标点/换行 | 会产生大量纯噪音 diff。只对**你自己新写**的文件统一 |
| 批量删"看起来没用"的中间文件 | 删除不可逆。音频、ASR JSON 都是重做校订的唯一凭据，先问 |
| **同时改两个变量然后就下因果结论** | 我换增益时顺手换了切片方式，于是把"切分才是主因"记成了"归一是主因"，写进文档后又花一轮才纠正（第二节） |
| 拿同一条管线的数字去论证另一条管线 | 固定分块的 81→208 字/分 不能用来解释 VAD 管线；128kbps/16k/VAD 每换一样都要重测 |

## 九、交付物清单（这个结构被验证好用）

2026-10 起，前三件由 `scripts/calibrate.py` 一条命令直接产出（`校订稿` / `改动台账` /
`待复核`），后三件按需手写：

| 文件 | 作用 | 谁产出 |
| --- | --- | --- |
| `N_校订稿.txt` × N | 分讲稿，可单独使用 | 工具 |
| `合集.txt` | 通读用 | 手写（拼合） |
| `改动台账.md` | **每处改动的行号、时间码、原、改、依据、原句** | 工具 |
| `待复核疑点.md` | 不确定的地方 + 原文 + 判断，交给用户裁决 | 工具（合并你手写的清单） |
| `校订说明.md` | 体例、改了什么类、**明确写了没改什么** | 手写 |
| `README.md` | 一页说清目录里是什么、怎么用 | 手写 |

台账是核心。它有行号和时间码，读者能对着音频核任何一条。
**没有台账的"校订稿"无法被检验，也就无法被信任。**

「待复核疑点」必须**如实**写：哪些改了、哪些没改、哪些查过确认不需要改。
第三种最容易被省略，而它恰恰是最有信息量的——它说明你查过了。

## 十一、这次差点没抓住的三件事（补记）

1. **多分 P 的时长陷阱**：`duration` 是总分 P 之和、`cid` 只是第 1 个分 P，
   于是"下载时长 < API 时长 × 0.2"把**正常公开课程**判成充电专属，
   一节课都转不出来（第三·五节）。它是"完整性校验"这个好习惯的副作用。
2. **VAD 在低电平上漏检**：症状是字/分低，但我先去查了增益（因为先前的
   结论指向增益），多花了一轮才想到量段数（第二节）。
3. **因果被变量混淆**：这是第 2 条的根因。教训不在"要控制变量"这句废话，
   而在**指标变好时最容易停止追问**——如果当时段/分只涨了 20%，我一定会
   继续查；正因为它涨了 2.6 倍，我就收工了。
4. **校验不响也没人发现**：把上一轮的"按行判残留"原样搬进 `calibrate.py` 时，
   它一次都不会触发（单遍替换不产生残留）。是写自测时才发现的。
   教训：**新的检查必须配一个能让它报警的输入**，否则它不是校验，是装饰（R44）。

## 十二、批量校订一个专题（15 讲是这么干的）

单篇校订是手工活；一整个专题（同一讲者、同一门课、十几讲）就该流水线化。

### 12.1 三张表

| 文件 | 内容 |
| --- | --- |
| `base.tsv` | 跨讲复用的规则（`以礼→仪礼`、`章句集著→章句集注`、`诸子→朱子`） |
| `<bv>_extra.tsv` | 本讲专属（引文、人名、篇题），读完这一讲才写得出来 |
| `overrides.tsv` | 复核时对专属表的人工修正：`bv 键 改后 依据`，改后留空 = 删掉这条 |

一条命令合并：`calibrate.py 稿子.md --rules base.tsv --rules <bv>_extra.tsv`

### 12.2 底表的复用率比想象的低

第一讲的 219 条底表，用到第二讲只命中 **50 处**、第三讲 **26 处**。
第一讲那 305 处大多是**那一讲的内容专有**（`诸子→朱子` 24 处、`以礼→仪礼` 18 处），
不是讲者的固定口音。所以**每讲都得真读一遍**，底表只省掉最浅的一层。

### 12.3 分工：分身只写规则，不碰稿子

读三万字找人名与引文错字是纯人力活，适合并行；但"改"必须集中做，口径才一致。
每个分身只交一张 TSV（原/改/依据），由上游统一应用。好处：

- 每条改动都有依据，台账口径统一；
- 分身写错一个键，`--check` 的"零命中"当场现形；
- 稿子只在一处被改，不会出现两个人对同一句下不同判断。

### 12.4 三条机器判据（不靠眼睛数）

```bash
calibrate.py 稿子.md --rules base.tsv --rules <bv>_extra.tsv --check --json rep.json
```

1. **`never_fired ∩ 本讲专属键 = ∅`** —— 键写错、被更长规则遮蔽、这份稿里本来没有，
   三种情况全在这里现形；
2. **`passes ≤ 2`** —— 超过 2 遍说明键里含着别的规则的产出（第五节④）；
3. **`--sample 10`** 随机抽十处，连上下文一起读，看改得对不对。

前两条能写成断言（`--json` 就是给上层断言用的），第三条只能人看。

### 12.5 分身交回来的表一定要人过一遍

实测一份 258 条的专属表里：

- 6 条零命中：5 条被更长的键遮蔽，1 条是线序依赖（`叫相怨` 先改成"乡愿"，
  短键 `相怨就是老好` 的上下文就没了）；
- 1 条把**错误形态**写进了"改后"（`…是讲慎读的 → …是讲慎读的`），要靠另一条规则
  第二遍才修好，白多一遍；
- 1 条人名理解错：`二成三曾` 不是"二程与曾"，是**二程三曾**——曾巩、曾布、曾肇三兄弟，
  跟上下文"家里出人物都是一窝一窝的"才对得上。

前两类机械检查抓得到，第三类只能人看。所以 `overrides.tsv` 必须逐条写理由：
**它是我复核的痕迹，也是将来重跑这份稿子的唯一依据。**

### 12.6 底表里的短键会跨讲改坏正字（这次最险的一处）

第一讲里 `以礼` 出现 18 次，**全部**是"仪礼"的误录（`以礼十七篇`、`以礼的附录`），
于是这条进了底表。到第四讲，同一个字符串全是正字：

```
齐之以礼　生事之以礼　死葬之以礼　祭之以礼　不以礼节之　以礼乐并用
所以礼的精神　所以礼这个字          ← 这七处会被改成"仪礼"
所以里面（原稿"以里"）               ← 会被改成"所仪礼面"
```

第四讲的分身自己发现了，加了 11 条空转守卫挡住。**但那是打补丁**：
后面每讲都可能冒出新的正字用法，逐个加守卫是打地鼠。

正确的修法是回到规则本身 —— **底表里的键必须自带上下文**：

| 坏写法（第一讲专用短键） | 好写法（自带上下文的键） |
| --- | --- |
| `以礼 → 仪礼` | `以礼的附录 → 仪礼的附录`、`以礼是典型 → 仪礼是典型`、`讨论以礼的时候 → 讨论仪礼的时候`…… |
| `以里 → 仪礼` | `这个以里的散篇 → 这个仪礼的散篇`、`所以以里的内容 → 所以仪礼的内容` |
| `诸子 → 朱子` | 保留裸键，但补 `诸子百家 → 诸子百家`、`先秦诸子 → 先秦诸子` 等**空转守卫** |

判断标准很简单：**这条键换个语境会不会指别的东西？** 会，就把它写长。

⚠️ 这类错误 `--check` 抓不到：规则**命中了**，只是命中错了地方。只有两件事能发现它 ——
① 分身/自己读别的讲时撞见；② 事后拿新表回测每一讲，数一数高危词（`仪礼`）有没有
突然冒出来。所以批量流程里要加一步**回测**：底表一改，就把已交付的各讲重跑一遍 `--check`，
看改动数有没有异常跳动。

### 12.7 一讲超过约 4.5 万字：拆半，别硬扛

这是 24 讲之后才踩出来的。前面二十来讲都是"一个分身通读全篇、交一张表"，
到 024 讲（49,310 字）连续三个分身**连文件都没建就断了**——不是他们不认真，
是"读 5 万字 + 记住几百种走音 + 逐条写键"这个任务本身超了单次上下文。

拆法（024 就是这么救回来的）：

```
partA：0 – 25000 字       →  calib/<bv>_partA.tsv
partB：25000 – 49310 字   →  calib/<bv>_partB.tsv
```

两班并行的提示词，除了"你只管前/后半段"，还要三条硬约束：

1. **每次只读 6000 字就停下写规则**，不是攒够几段一起写。切片命令：

   ```python
   python -c "import pathlib;p=pathlib.Path(r'稿子.md');b=p.read_text(encoding='utf-8').split('---',2)[2].strip();print(b[0:6000])"
   ```

2. **读完一段立刻 `>>` 追加**，不要留到最后一次性写。中途断掉也只丢最后一段。
3. 明说"只管 0–25000"，否则两班会重复劳动。

合并用 `scripts/merge_rules.py`，别手搓：

```bash
python scripts/merge_rules.py 稿子.md calib/<bv>_partA.tsv calib/<bv>_partB.tsv \
    --base calib/base.tsv -o calib/<bv>_extra.tsv --json rep.json
```

它按键去重（**先出现的赢**，所以 partA 放前面）、丢掉稿中不存在的键、丢掉撞底表的条目，
最后报每份表的**覆盖区间**。024 实测：A 段 210 条覆盖 0–49.9%、B 段 192 条覆盖 50.7–99.6%，
合并丢掉 7 条重复（`普鲁东`、`普鲁通`、`心而上学` 等两边都收了的）→ 395 条，
跑出 551 处改动、1 遍收敛。

**覆盖率是这条流水线上最便宜的体检**：

```
覆盖率 = 该表最远的那个键在正文里的结束位置 / 正文总长      # 分母不含 frontmatter
```

它比"我读完了"这句自述可靠得多。负责后半段的人报 60%，就是没读完；
负责前半段的人报 100%，就是越界读了别人的部分（或者读的根本是别的讲）。低于 90% 脚本会警告。

### 12.8 分身"静默死亡"：别看回话，看三个可测事实

这一批 7 讲里，有 **3 讲**的分身是"活儿干完了但没回话"就断的（014、025，以及 024 的 partA）。
所以验收**不能**以收到 closing message 为准，也不能以"没收到"就当没干活。
每次都去看文件、量三个数：

```bash
# ① 表在不在、是否三列、键有无重复        → merge_rules.py 或 calibrate 都会报
# ② 每个键是否真的落在正文里（写错一字就永远打不着）
# ③ passes ≤ 2 且 never_fired ∩ 本讲专属键 = ∅
python scripts/calibrate.py 稿子.md --rules calib/base.tsv --rules calib/<bv>_extra.tsv --check
```

再加一条覆盖判据（上面 12.7 那个公式）。几个数都过，这份表就能用，**分身回不回话无关紧要**：
014 就是这么交付的——分身失联，但表已覆盖全文 100%、281 条键全部真实存在、2 遍收敛，直接落盘。

更危险的一种相反情况是**活儿干了一半却回了话**（"已完成"）。
所以"回了话"同样不能当证据。两种状态用同一套判据，这是这套流程里唯一稳的地方。

⚠️ 还有一种半死状态：分身**直接改了稿子**（任务书明明只说"交规则表"）。
014 的分身就这么干了——把规则应用到了 `transcripts/<bv>.md` 上，还留了一份台账。
这时再拿新表去 `--check`，会看到"改动 0 处、285 条全部零命中"，**别以为表写错了**：
先看正文是不是已被改过（比对字数、看目录里有没有 `<bv>_改动台账.md`）。
处理办法是认这份稿子（判据仍是：全角标点已清零、FFFD 0、收敛 ≤2 遍、专属键零命中 0），
走"机械层空跑"落盘——喂一张只有底表的规则表让它原样输出，不要再套专属表。

### 12.9 自食的第三种形态：值只比键多一个字

§5.2 记了四种自食陷阱（短键污染已改文本、等长 tie-break、键是正确词的子串、值含 key）。
批量跑下来最常复发的是**第三种的一个变体**——键本身没错，但**替换后会新长出一个字符**：

| 键 | 值 | 每遍 |
|---|---|---|
| `隶社会` | 奴隶社会 | 多一个「奴」 |
| `族和平民` | 贵族和平民 | 多一个「贵」 |
| `850年9月份` | 1850年9月份 | 多一个「1」 |
| `巴达克起义` | 斯巴达克起义 | 多一个「斯」 |
| `本论` | 资本论 | 多一个「资」 |

症状：`--check` 报"8 遍内没有收敛"，而规则表本身看起来完全正常。
**修法不是加空转守卫**（`理性批判→理性批判` 那种），而是**把键往前挪一个真实字符**：

```diff
- 隶社会	奴隶社会
+ 。隶社会	。奴隶社会
```

守卫只是把自食掩盖住（每遍仍命中、白跑一遍）；往前挪一是让键**真的不再命中自己产出的文本**，
二是顺便把键绑到了上下文（`。850年9月份` 不会碰「29850年」）。026、027、034、038、039、043、044
七讲都撞过这一型，挪字符后全部回到 1–2 遍收敛。

**另一件合并时才发现的误读**：`merge_rules.py` 的覆盖率是"该份最远的键 ÷ 全文长度"，
拆半时**前半份的覆盖率天然偏低**——人名、篇名这类键在两半都出现，会被算到后半去。
041 实测：partA 报 83.1%、partB 报 99.4%，而 partA 读的正是 0–24500。
判据要看**命中区间的上限有没有超出自己那半段**，不是看百分数（脚本已把这段判读写进告警）。
